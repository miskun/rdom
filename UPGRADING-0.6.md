# Upgrading from rdom 0.5 to 0.6

rdom 0.6 makes its CSS behave as the web platform's does: the initial values, the box model, flexbox, tables, lists, text and the cascade follow their specifications, and the properties 0.5 dropped as unknown now take effect. A 0.5 app needs a few code changes to compile, and renders differently in a handful of predictable places.

Start with the [Top 15](#top-15--what-most-05-apps-hit): the changes most 0.5 apps hit, each with its fix. If something looks wrong and you do not know why, the [By symptom](#by-symptom) index maps what you see to the entries that explain it. [All behaviour changes, by area](#all-behaviour-changes-by-area) lists every change that compiles unchanged but renders or reads differently, and [Compile breaks](#compile-breaks) and the [API changes table](#api-changes-from-05) list what no longer compiles.

[`CHANGELOG.md`](CHANGELOG.md)'s `[Unreleased]` section lists every addition and fix by crate. The full story of each change is in [`specs/CSS-COMPLETE-2026-10.md`](specs/CSS-COMPLETE-2026-10.md)'s Log, by the item id that ends each entry. Every deliberate departure from the web platform is in [`specs/DIVERGENCES.md`](specs/DIVERGENCES.md).

Lengths are terminal cells: a bare number is cells, and a pixel or font-relative length (`px`, `em`, `rem`, …) never becomes geometry — `width: 10px` is dropped as invalid. Such a length only selects: a border's glyph weight, and which rules a `@media` / `@container` query or `column-width` picks, at 8px a column and 16px a row (DESIGN, "Pixel lengths select, cells measure").

## Top 15 — what most 0.5 apps hit

Ranked by how many 0.5 apps they reach and how visible the result is. Each row names what you see, the fix, and links to the full entry below.

| # | Change | What you see | Fix |
|---|---|---|---|
| 1 | [`display: flex` is a row](#sc-flex-row) | Flex containers lay their children out side by side instead of stacked. | `flex-direction: column` (`.flex_column()`) on every container that relied on the old default. |
| 2 | [The root lays out in block flow](#sc-root-block) | The app no longer fills the screen; `flex: 1` panes collapse to their content. | `body, .app { height: 100% }` — every ancestor of the app's top element, not the top element alone — and `display: flex; flex-direction: column` where panes should fill. |
| 3 | [Boxes are `content-box`](#sc-content-box) | Bordered or padded boxes are wider and taller than their `width` / `height`. | `*, ::before, ::after { box-sizing: border-box }`. |
| 4 | [Flex items keep their automatic minimum](#sc-flex-grow) | A `flex: 1` pane holding a long line or a table overflows instead of shrinking to its share. | `min-width: 0` on the pane (`min-height: 0` in a column). |
| 5 | [HTML tables are CSS tables](#sc-tables) | Tables are only as wide as their columns, cells wrap, `<th>` is centred. | `table { width: 100% }`, `td, th { white-space: nowrap }`, exact widths with `table-layout: fixed`; see [the port below](#porting-a-column-synced-table). |
| 6 | [The root's background fills the screen; `:root` is styled](#sc-root-canvas) | A top-level element's background no longer paints the whole screen; `:root { color }` now reaches every element. | Put the screen colour on `:root` or `<body>`; see also [`sc-root-element`](#sc-root-element). |
| 7 | [Abspos boxes sit in the padding box](#sc-abspos-padding-box) | A title or badge drawn on a panel's border lands one row down and one column right. | Subtract the border from each inset: `top: -1; left: 1` instead of `top: 0; left: 2`. |
| 8 | [Overflowing text paints past its box](#sc-overflow-text) | Extra lines of a fixed-height box show below it. | `overflow: hidden` (or `clip`) on the box. |
| 9 | [`@media`, `@supports` and `@container` apply](#sc-conditional-rules) | A shared web sheet turns dark (`prefers-color-scheme: dark` matches on most terminals); pixel breakpoints switch at real widths. | Pin the scheme with `App::with_color_scheme(ColorScheme::Light)` when the sheet's light colours are the app's, or drop the dark block; a `min-width: 768px` block applies from 96 columns. |
| 10 | [`transform` and `translate` take effect](#sc-transforms) | `top: 50%; left: 50%; transform: translate(-50%, -50%)` centres for real; a `:hover { transform: scale(1.02) }` card becomes a stacking context and the containing block of its fixed descendants. | Drop transforms that were there for a browser only; move a `position: fixed` child out of a transformed ancestor. |
| 11 | [`appearance: none` strips UA chrome](#sc-appearance-none) | A reset's buttons lose their `[ ]`, selects their `▾`, checkboxes their mark. | Remove a browser-only `appearance: none`, or draw the mark: `input[type=checkbox]::before { content: '[ ] ' }`. |
| 12 | [`line-height` takes effect](#sc-line-height) | A browser sheet's `line-height: 2` double-spaces every line. | `line-height: normal` (or `1`). |
| 13 | [List markers hang outside the item](#sc-list-markers) | Bullets moved off-screen (`ul { padding: 0 }`), or appear twice with a custom `li::before`. | `list-style-position: inside`, or keep the padding; move custom markers to `li::marker { content: … }`. |
| 14 | [Focus scrolls into view](#sc-focus-scroll) | Tab or `focus()` scrolls the page; snapshots shift. | `focus_with(FocusOptions::new().prevent_scroll(true))` where the scroll is unwanted. |
| 15 | [A modal dialog is centred over an inert page](#sc-modal-dialog) | `show_modal` covers the content instead of sitting in flow; clicks outside it do nothing. | Style `dialog:modal` to place it elsewhere; use `dialog::show` for a non-modal dialog. |

The next ones by reach: [`sc-canvas-hit`](#sc-canvas-hit) (a click on empty screen targets the root, not nothing), [`sc-root-element`](#sc-root-element), [`sc-legacy-clip`](#sc-legacy-clip), [`sc-text-properties`](#sc-text-properties), [`sc-canvas-backgrounds`](#sc-canvas-backgrounds).

The fixes that are code, in one place:

```rust
use rdom_tui::prelude::*;

// sc-flex-row: a stack says so.
fn stack() -> TuiStyle {
    TuiStyle::new().flex_column()
}

// sc-canvas-hit: the element under (x, y), `None` on the empty canvas —
// 0.5's answer, where 0.6 returns the root.
fn hit_content(dom: &TuiDom, x: i32, y: i32) -> Option<NodeId> {
    let hit = dom.element_from_point(x, y)?.id();
    (hit != dom.root()).then_some(hit)
}

// sc-focus-scroll: focus without scrolling the element into view.
fn focus_in_place(dom: &mut TuiDom, id: NodeId) {
    dom.node_mut(id)
        .focus_with(FocusOptions::new().prevent_scroll(true));
}
```

### Layout, positioning and overflow

- <a id="sc-inline-block-margins"></a>**An inline block's left and right margins now apply** (CSS 2.1 §10.3.9): `display: inline-block` boxes — buttons in a toolbar line, badges, chips — ignored `margin-left` / `margin-right` and sat flush against the text and atoms beside them; they now keep those cells, so a line with such margins is wider and may wrap sooner. A negative one still counts as zero. (ACID-FIX-10)
- <a id="sc-inline-anchor"></a>**A box anchored to an inline element shows, at the element** (CSS Anchor Positioning 1 §2): with an `anchor-name` on a `<span>`, `<a>` or other inline element, the anchored box was hidden (its anchor read as 0 × 0 and clipped); it is now placed against the bounding box of the element's text. (ACID-FIX-11)
- <a id="sc-relative-inline"></a>**`position: relative` moves an inline element** (CSS 2.1 §9.4.3): a `<span style="position: relative; top: -1">` drew where it was laid out; its text (and any inline block in it) now draws, and is hit, at the offset, its line keeping the cells it took. A sheet that set `position: relative` with insets on inline elements expecting nothing to move sees them move. (ACID-FIX-5)
- <a id="sc-flex-row"></a>**`display: flex` is a row.** `flex-direction`'s initial value is `row` (CSS Flexbox §5.1; it was `column`). Add `flex-direction: column` (`.flex_column()`) to every flex container that stacked its items without saying so. (C6-FLEX-DIRECTION-INITIAL)
- <a id="sc-root-block"></a>**The document root lays its children out in block flow, not a viewport flex column** (CSS 2.1 §10.1, §9.4.1): the root fragment's box is the initial containing block — the viewport's size — and its children lay out as `<body>`'s do. A top-level element's `auto` height is its content's, so `flex: 1` / `flex-grow` on it fills nothing, and one taller than the viewport is no longer shrunk to fit; vertical margins between top-level elements and their first / last children collapse (they added up, or stayed inside); top-level floats float; top-level inline-level elements and text share lines, side by side, where they stacked. Migration: give the app's top element `height: 100%` (or `min-height: 100%`) — a percentage of the viewport now — and every ancestor between the root and it too, since a percentage of an `auto` height is `auto` (CSS 2.1 §10.5): a tree parsed from `<body><div class=app>` needs `body, .app { height: 100% }`, not `.app { height: 100% }` alone; with `box-sizing: border-box` if it has padding or a border, and `display: flex; flex-direction: column` if `flex: 1` panes inside it are to fill the screen; wrap stacked top-level inline elements in a block. An element root (`Dom::with_root_tag`) is a block as tall as its content: `html { height: 100% }`. (C13-ROOT-BLOCK)
- <a id="sc-content-box"></a>**Boxes are `content-box`.** `width` / `height` / `min-*` / `max-*` no longer include padding and border (CSS UI 3 §3.1). `*, ::before, ::after { box-sizing: border-box }` restores the old sizing, except that a box is floored at its padding plus border and `min-height` / `max-height` on an `auto` height bound the border box. (C5-BOX-SIZING)
- <a id="sc-flex-grow"></a>**Flex items grow from their flex base size and keep their automatic minimum** (CSS Flexbox §4.5, §9.2, §9.7): `flex: 1 1 auto` keeps its content's share (it behaved as `flex: 1 1 0%`), `flex: <n>` has a basis of `0%`, an item no longer shrinks below its min-content size, and `auto` margins take the space left after `flex-grow`. **A `flex: 1` pane holding wide content (a long line, a table) needs `min-width: 0`** (or `min-height: 0` in a column) to shrink to its share. (C6-FLEX-LONGHANDS, C6G-FLEX-SPEC, C6G-FLEX-BASIS-ZERO)
- <a id="sc-abspos-padding-box"></a>**An absolutely positioned box is placed in its positioned ancestor's padding box** (CSS 2.1 §10.1): its insets count from inside the ancestor's border, for elements and positioned `::before` / `::after` alike, and a grid's `auto` line is that padding edge (CSS Grid 2 §9.1). The common case is a title or badge drawn *on* a bordered panel's border — `position: absolute; top: 0; left: 2` in a `position: relative` panel — which now lands one row down and one column right, inside the panel: subtract the border width from each inset (`top: -1; left: 1`). A `position: sticky` ancestor now contains such a box too, the padding box excludes a scrollbar gutter, and a positioned scroll container's box scrolls with its content. (C7-ABSPOS-PADDING-EDGE, C8-CB-COMPLETE)
- <a id="sc-overflow-text"></a>**Overflowing text paints past its box**: a fixed-height or narrow box's extra lines and columns show unless the box has `overflow: hidden` / `clip` (CSS Overflow 3 §3.1); add one to keep them cut. (C8-OVERFLOW-TEXT)
- <a id="sc-collapsed-margins"></a>**Block content is measured with collapsed margins** (CSS 2.1 §8.3.1, CSS Sizing 3 §5.2): a flex or grid item, a float, an inline block or a `fit-content` box sized from block children with vertical margins is a row shorter for each pair of adjoining margins (they were summed), and an inline block's `auto` width is shrink-to-fit (§10.3.9: its text wraps in a narrow line instead of overflowing). (C8G-FLOAT-MEASURE)
- <a id="sc-abspos-scroller"></a>**An absolutely positioned box widens its scroller** (CSS Overflow 3 §2.2): a box placed past the content of the nearest scroll container at or above its containing block counts in its scrollable overflow — a dropdown inside an `overflow: auto` pane brings up the pane's `auto` scrollbar, whose gutter narrows the content and reflows it. Give the dropdown's containing block `overflow: visible` or place it in an ancestor that does not scroll. (C8-ABSPOS-OVERFLOW)
- <a id="sc-multicol"></a>**`columns`, `column-count` and `column-width` lay content out in columns** (CSS Multi-column 1): they were dropped as unknown properties in 0.5; a box with either now flows its content through column boxes side by side — balanced, or filled in turn under a constrained height — its `auto` height the columns', and a block that falls across a column break is drawn and hit as its fragments, and `column-rule` draws between the columns. `break-before` / `-after: column` force a break. (C15-COLUMNS)
- <a id="sc-anchor"></a>**Anchor positioning takes effect** (CSS Anchor Positioning 1): `anchor()`, `anchor-size()`, `position-area` and `anchor-center` were dropped as invalid in 0.5; an absolutely positioned box using them now places against its anchor — a popover with `position-area` against its invoker, which it hugs (an `auto` margin is 0 there). (C15-ANCHOR)
- <a id="sc-aspect-ratio-block"></a>**`aspect-ratio` sizes block-level boxes** (CSS Sizing 4 §5.1): in block flow it applied only to flex and grid items; now a block with an `auto` height takes the ratio of its width (at least its content), and one with a definite height takes its width from the ratio instead of stretching. (C14-ASPECT-BLOCK)
- <a id="sc-block-flex-direction"></a>**Block containers ignore `flex-direction`**: a block's children stack on its block axis whatever it says (it is a flex-container property). (C6-FLEX-DIRECTION-INITIAL)
- <a id="sc-overflow-axes"></a>**`overflow` axes are paired** (CSS Overflow 3 §3.1): `overflow-y: scroll` computes `overflow-x` to `auto` (it stayed `visible`), so wide content now scrolls instead of painting past the box; `scrollbar-gutter: stable` no longer reserves a bottom row; and a scroll offset written on a box that is not a scroll container is dropped at the next layout — scroll the box that has `overflow` set. A stylesheet's `overflow: clip` — dropped as invalid in 0.5 — now clips. (C8-OVERFLOW-CLIP)
- <a id="sc-flex-item-display"></a>**A flex item's computed `display` is block-level** (`inline` → `block`, `inline-block` → `block flow-root`, CSS Display 3 §2.7), and an `inline-block` item stretches. (C6G-BLOCKIFY, C6G-FLEX-SPEC)
- <a id="sc-anonymous-flex-items"></a>**Flex containers lay out their text and `::before` / `::after` as items** (CSS Flexbox §4): text beside element items, and pseudo-elements, were dropped; a text-only container's text is one item, which `justify-content` / `align-items` place and `text-align` does not. (C6G-ANON-FLEX-ITEMS, C6G-PSEUDO-FLEX-ITEMS)
- <a id="sc-min-auto"></a>**`min-*: auto` does not floor a flex item's cross size** at its content (the automatic minimum is a main-axis rule). (C3G-MIN-AUTO)
- <a id="sc-z-index-flex"></a>**`z-index` on a static flex item stacks it** (CSS Flexbox §5.4): a numeric `z-index` makes a flex or grid item a stacking context ordered by it, as a positioned box's is; it was ignored without `position`. (C7-GRID-PLACE)
- <a id="sc-gutter-hidden"></a>**`scrollbar-gutter: stable` reserves the gutter on an `overflow: hidden` box too** (CSS Overflow 3 §3.3): such a box's content is a column narrower. (C8-SCROLLBAR)
- <a id="sc-scrollport"></a>**A padded scroller's bar sits at its padding edge, and its end is reachable** (CSS Overflow 3 §2.2, §5.2): the bar moved from beside the content box to the column inside the border; `scrollHeight` / `scrollWidth` count the padding and are never less than the scrollport; content is clipped out of the gutters. (C8G-SCROLLPORT)
- <a id="sc-webkit-box"></a>**A vertical `display: -webkit-box` is a column, and a flex container draws no `text-overflow` marker** (Compat Standard §5, CSS Overflow 4 §3): its children stacked where they sat in a row; a `display: flex; text-overflow: ellipsis` box's text is clipped without `…`. (C8G-WEBKIT-CLAMP)
- <a id="sc-relative-in-flow"></a>**A relatively positioned box is laid out in flow, then shifted** (CSS 2.1 §9.4.3): its subtree is laid out where the box is in flow and moved with it, so a float inside it excludes the next paragraph's lines at the unshifted place. (C8-FLOAT)
- <a id="sc-abspos-shrink"></a>**An `auto`-width absolutely positioned box wraps where its containing block ends** (CSS 2.1 §10.3.7): its width is shrink-to-fit — `min(max(min-content, available), max-content)` — so a long tooltip at `left: 30` in 80 columns wraps at 50 cells, and an anchored one wraps beside its anchor instead of overflowing into a fallback; it was its max-content width. (C15G-ABSPOS-CLAMP)
- <a id="sc-stretch"></a>**`width: -webkit-fill-available` (and `stretch`, `-moz-available`) fills** (CSS Sizing 4 §3.1): the value was dropped as invalid, so a box sized by it took its `auto` size; now its margin box fills the containing block on that axis (a definite one for heights). (C15G-STRETCH)

### Tables

- <a id="sc-junction-arms"></a>**A border junction draws the line that won next to it** (CSS Tables 3 §11.5): where a box's side stops short of a junction — a collapsed table cell with no border on the line above it — the junction drew the arm of a losing border; it now joins the winning one (`╥` where it drew `┬`) in the winner's colour. (ACID-FIX-7)
- <a id="sc-heavy-double-corner"></a>**A thick border meeting a double one draws a heavy corner**: where Unicode has no glyph for the lines meeting, the corner showed the double side as a light line (`┚`); the dominant (thicker) side's set now draws the whole cell (`┛`). (ACID-FIX-12)
- <a id="sc-tables"></a>**HTML tables lay out as CSS tables** (CSS 2.1 §17, HTML §15.3.8; the flex-row tables are gone) — every `<table>`, with no author CSS involved. An `auto`-width table is as wide as its columns, not its container (its border and background hug them); a `<tr>` is as tall as its tallest cell and centres its other cells (HTML's UA `vertical-align: middle`); `rowspan`, `<col>` / `<colgroup>` widths and `visibility: collapse`, `<tfoot>` last, `<caption>` outside the table's border and `border-spacing` apply; an `rtl` table lays its columns right to left. A `<th>` is centred over its column unless an ancestor sets `text-align` (HTML's conditional `th` rule; `th { text-align: start }` restores 0.5), a `<caption>` is centred, neither italic nor muted, and `<tr>` inherits `vertical-align` and `border-color` from its row group. Migration: (a) `table { width: 100% }` fills the container — the UA `table` is now `box-sizing: border-box`, so a bordered one fits; (b) the extra width is spread over the columns by their max-content widths, so 0.5's content-wide, left-packed columns do not come back; (c) cells wrap — `td, th { white-space: nowrap }` keeps rows one line; (d) a cell's `width` is a minimum in the automatic layout (wider content widens the column) — exact widths need `table-layout: fixed` and a table `width`, the first row sizing the columns; (e) `td { flex: 1 }`, `gap` on the table and cell margins no longer apply (CSS 2.1 §17.5: a cell has no margins) — use `border-spacing`, padding or a positioned box instead. Column widths are `node.table_tracks()?.columns()[i].len()`. A column-synced virtual table ports as below. (C13-TFC, C13G-TH-CAPTION, C13G-TABLE-UA, C13G-TABLE-TRACKS, C13G-UPGRADE)

### Porting a column-synced table

The [`sc-tables`](#sc-tables) migration for rdom-virtualtable's shape, pinned by `css_phase13/upgrade.rs`. 0.5 set `width` on each header cell, re-ran `size_columns` after every window change, read `table_used_width` and pinned an overflow chip right with a header cell's `margin-left: auto`. In 0.6:

```css
.pane  { position: relative }
table  { table-layout: fixed; width: 100% }      /* the header row sizes the columns, exactly */
th.name { width: 10 } th.size { width: 4 }        /* content widths; padding adds to the column */
td, th { white-space: nowrap; overflow: hidden }  /* one-line rows, long cells clipped */
.chip  { position: absolute; top: 0; right: 0 }   /* moved out of the table, into the pane */
```

A column's width, read after layout — no `size_columns`, no `table_used_width`:

```rust
use rdom_tui::prelude::*;

fn column_width(dom: &TuiDom, table: NodeId, i: usize) -> Option<usize> {
    dom.node(table).table_tracks().map(|t| t.columns()[i].len())
}
```

Rows materializing in the window cannot move the columns under `fixed`, which only reads the first row.

### Lists, pseudo-elements and generated content

- <a id="sc-list-markers"></a>**List markers are `::marker`s that hang outside the item** (CSS Lists 3 §3, HTML §15.3.8): `ul` / `ol` bullets and numbers were the UA's `li::before`, inside the line; they are each `li`'s `::marker`, from `list-style-type`, hung in the list's padding — four cells for `ul`, `ol` and `menu` (two in 0.5), so a list's content moves two cells right — with wrapped lines under the text. An `li::before` is an ordinary pseudo-element now: a sheet that drew its own marker there gets both (set `list-style: none` on the list, or move the rule to `li::marker { content: … }`), and an `li::before { color: red }` that coloured the UA bullet styles nothing of it — write `li::marker { color: red }`. **A `ul { padding: 0 }` hangs its bullets left of the list**, off-screen at column 0 (0.5 kept them in the line): add `list-style-position: inside`, or keep the padding. (C10-LIST-ITEM, C10G-MARKER-CLIP)
- <a id="sc-nested-bullets"></a>**Nested bullet lists draw `◦` and `▪`** (HTML §15.3.8): a `ul` or `menu` inside a list shows `circle` bullets, one more level down `square` — every level drew `•`. Set `ul ul { list-style-type: disc }` for the old look. (C10-LIST-ITEM)
- <a id="sc-pseudo-no-content"></a>**A `::before` / `::after` without content has no style** (CSS Pseudo-Elements 4 §2, CSS Lists 3 §4.5): with `content: none` or `normal` (its initial value) it generates no box, so `computed_pseudo` / `computed_before` read `None` (they held a style with no content) and its `counter-increment` / `-reset` / `-set` no longer apply. (C12G-PSEUDO-GONE)
- <a id="sc-pseudo-display"></a>**`display` and `float` on `::before` / `::after` take effect**: such a pseudo-element was inline text in its host's line; `display: block` now makes it a block box above (below) the host's content, `inline-block` a box in the line (its `width`, padding and border drawn), `float` a float, `flex` / `grid` a container of its text, and `display: none` hides one that used to show. (C8G-PSEUDO-BOXES, C8G-PSEUDO-ATOMS)
- <a id="sc-positioned-pseudos"></a>**Positioned `::before` / `::after` stack, hit and scroll as elements** (CSS Pseudo 4 §2, CSS 2.1 Appendix E): an absolutely or fixed positioned pseudo-element paints in its host's stacking context by its own `z-index` (it painted above everything), so a sibling context with a higher `z-index` covers it and `z-index: -1` puts it under its host's text; a click on it targets its host; an axis with both insets `auto` starts at its static position. A relatively positioned or sticky one takes room in its host's line, then moves. (C10-PSEUDO-UNIFY, C10G-MARKER-HIT)
- <a id="sc-quotes"></a>**`<q>` draws quotation marks** (HTML §15.3.4, CSS Generated Content 3 §2.2): the UA's `q::before { content: open-quote }` / `q::after { content: close-quote }` add “ ” (‘ ’ nested, the `lang`'s marks under `quotes: auto`), so a `<q>` whose text already has quotes shows them twice. Remove the literal quotes, or set `q { quotes: none }`. (C10-CONTENT)
- <a id="sc-list-type-attr"></a>**`<ol type>`, `<ul type>` and `<li type>` take effect** (HTML §15.3.8): `<ol type="a">` numbers its items `a.`, `b.` (it was `1.`, `2.`), `A`, `i` and `I` likewise, and `<ul type="square">` draws `▪`; an author `list-style-type` still wins. Remove a stale `type` to keep the default markers. (C10G-MARKER-HIT)
- <a id="sc-placeholder"></a>**`::placeholder` takes the `::first-line` properties**: `text-transform`, `letter-spacing`, `word-spacing` and every background property now apply to a placeholder (they were dropped), so an `input::placeholder` rule written for a browser may change its look. (C10-FIRST)
- <a id="sc-marker-click"></a>**A click on an outside marker targets its list item**: a pointer over a bullet or number hits the `li` (and `::marker:hover` applies), where it hit the `ul` / `ol` whose padding the marker hangs in. (C10G-MARKER-HIT)
- <a id="sc-counter-none"></a>**`li { counter-increment: none }` no longer stops numbering** (CSS Lists 3 §4.6): a list item increments `list-item` implicitly unless `counter-increment` names `list-item` itself; write `counter-increment: list-item 0` to hold the number. (C10-COUNTERS)
- <a id="sc-inline-list-item"></a>**An inline list item shows its marker**: `display: inline list-item` — on an element, `::before` or `::after` — puts the marker before its content, in the line (CSS Lists 3 §3.5: `outside` acts as `inside` for an inline box); it showed none. (C10G-INLINE-LIST-ITEM)

### Text

- <a id="sc-line-height"></a>**`line-height` takes effect** (CSS Inline 3 §5.1, CSS 2.1 §10.8): it was dropped as an unknown property; a line is now its line height in whole rows, half the leading above the glyph row and half below — floored, so a browser stylesheet's `line-height: 1.5` keeps one row per line and `2` or `2.5` spaces lines two rows apart (set `line-height: normal` or `1` for one row per line) — and `lh` / `rlh` follow it (they were one row). A click on a leading row puts the caret in that line's text. (C9-LINE-HEIGHT, C2-LH, C9G-LINE-HEIGHT-FLOOR)
- <a id="sc-text-properties"></a>**The CSS Text properties take effect** (CSS Text 3 / 4): `text-align` (with `-last` and `text-justify`), `text-transform`, `text-indent`, `word-break`, `overflow-wrap` / `word-wrap` and `text-wrap` were all dropped as unknown properties in 0.5; a 0.5 sheet's `.title { text-align: center; text-transform: uppercase }` now centres and uppercases its text. Remove a declaration that was only there for a browser. (C9-TEXT-ALIGN, C9-TEXT-TRANSFORM, C9-TEXT-INDENT, C9-BREAKING, C9-TEXT-WRAP)
- <a id="sc-text-decoration"></a>**Text decorations propagate, and the full `text-decoration` takes effect** (CSS Text Decoration 4 §2): an element's underline or line-through now reaches its descendants' text (`<a href><b>x</b></a>` underlines the `x`; it did not), drawn in the decorating box's color — the decorating box's `color` for an underline, through SGR 58 where the terminal has it — but not into an inline block or a float; `overline`, combinations (`underline line-through`), `wavy` / `double` / `dotted` / `dashed` and a color, which were dropped, now apply. Set `text-decoration: none` on the descendant's ancestor, not the descendant, to remove one (as in a browser). (C9-DECORATION)
- <a id="sc-vertical-align"></a>**`vertical-align` takes effect, and `<sub>` / `<sup>` move off the baseline** (CSS 2.1 §10.8.1, HTML §15.3.4): it was dropped as an unknown property; inline elements, generated text and inline blocks now sit where it puts them, in whole rows, the line growing to hold them — so `x<sup>2</sup>` takes two rows, the `2` above the `x` (the UA sheet's `sup { vertical-align: super }`). Set `sup, sub { vertical-align: baseline }` for the old look. (C9-VERTICAL-ALIGN)
- <a id="sc-white-space"></a>**`white-space` applies to each element's text, and `pre-wrap` spaces hang** (CSS Text 3 §3, §4.1): a `<span>`'s own `white-space` now governs its text inside a block of another (the block's governed every line); spaces ending a soft-wrapped `pre-wrap` line (a `<textarea>`'s) stay on it, hanging past the edge, where they used to wrap to the start of the next line; a `nowrap` line too wide for the room beside a float moves below it (it is one unbreakable piece); and a line feed between two Chinese or Japanese characters joins them without a space. (C9-WHITE-SPACE)
- <a id="sc-font"></a>**Numeric font weights and `oblique` draw, and `font` takes effect** (CSS Fonts 4 §2.2, §2.4, §3.7): `font-weight: 600` … `1000` and `bolder` are bold (they were dropped, or only `bold` counted), `oblique` is italic, and the `font` shorthand — dropped before — sets the weight and style and resets `line-height`, so `font: 14px/2 sans-serif` spaces lines two rows apart. (C9-FONT)
- <a id="sc-line-breaking"></a>**Lines break by a UAX #14 subset** (CSS Text 3 §5): closing punctuation (`。` `、` `）`), small kana and iteration marks no longer start a line and opening punctuation no longer ends one (any two-cell character broke on both sides); a soft hyphen (U+00AD) is now a break opportunity that shows `-` (it was dropped), a zero-width space and `<wbr>` are opportunities, and U+2028 / U+2029 force a break. Set `hyphens: none` to ignore soft hyphens. (C9-BREAKING)
- <a id="sc-tab-stops"></a>**A preserved tab advances to its tab stop** (CSS Text 3 §4.2): in `pre`, `pre-wrap` and `<textarea>` text a tab moves to the next multiple of `tab-size` (initial 8) from the block's edge — it was one space. Set `tab-size: 1` for the old look. (C9-TAB-SIZE)
- <a id="sc-spacing"></a>**`letter-spacing` and `word-spacing` take effect** (CSS Text 3 §9): they were dropped as unknown properties; a length in cells now spaces text in whole blank cells, so `.title { letter-spacing: 1 }` draws `T I T L E`. A browser sheet's `letter-spacing: .1em` is still dropped (font-relative). (C9G-LETTER-SPACING)
- <a id="sc-rtl-overflow"></a>**An overflowing `rtl` line hangs off the left edge** (CSS Text 3 §7.1): a line wider than its `rtl` block starts at the right edge and overflows the left one, reached with a negative `scrollLeft` (it started at the left edge and overflowed the right). (C8-RTL-LINE-OVERFLOW)
- <a id="sc-abbr"></a>**`abbr[title]` is underlined dotted, and a bare `<abbr>` is not underlined** (HTML §15.3.4): an `<abbr>` with a title takes `text-decoration: dotted underline` (SGR `4:4`, solid where the terminal has no styled underlines); one without a title lost its underline. (C9G-DOCS)
- <a id="sc-dir-auto"></a>**`dir=auto` and `<bdi>` set `direction`** (HTML §3.2.6.4, §15.3.5): the UA's `dir` rules use `:dir()`, so an element with `dir=auto` (or a `<bdi>`) whose first strong character is Hebrew or Arabic right-aligns its lines and flips its scroll origin; an invalid `dir` takes its parent's directionality. Write `dir=ltr` to keep a field left-to-right. (C11-LINK-LANG)

### Colour and painting

- <a id="sc-root-canvas"></a>**The root's background fills the screen** (CSS Backgrounds 3 §2.11.2): the root fragment is the root element, so `:root { background-color: … }` paints the whole viewport, beneath everything; under a transparent root an `<html>` child's background propagates, else its `<body>`'s, else a `<body>` child's, and that element paints none on its own box. Any other top-level element paints only its own box — put an app's screen colour on `:root` or a `<body>`. (C13-ROOT-CANVAS, C14G-ROOT-ELEMENT)
- <a id="sc-canvas-backgrounds"></a>**`Canvas` / `reset` backgrounds paint, and `<dialog>` hides what it covers** (CSS Backgrounds 3 §3.2, HTML §15.3.3): a specified `Canvas` / `reset` blanks its cells in the terminal default background (it painted nothing), and HTML gives every `dialog` `background-color: Canvas; color: CanvasText` — so a non-modal dialog in flow blanks its own box, and a `[popover]` covers the page. Set `background-color: transparent` on one that must show through. (C11G-CANVAS-FILL)
- <a id="sc-outline"></a>**`outline` declarations draw** (CSS UI 4 §5): `outline` and its longhands were dropped as unknown properties; a browser sheet's `:focus-visible { outline: 2px solid }` or `.card { outline: 1px dashed }` now draws a ring of border glyphs one cell outside the box — an inline element's around each line's fragment — over its neighbours, as it takes no room. Remove an outline that was there for a browser only. (C12-OUTLINE, C12G-OUTLINE-INLINE)
- <a id="sc-transparent-bg"></a>**A computed `bg` starts `Color::TRANSPARENT`** (CSS Backgrounds 3 §3.2): `background-color`'s initial value is `transparent`, so an unstyled element's `computed.bg` reads `Color::TRANSPARENT`, not `Color::Reset`; code that tested `bg == Color::Reset` for "no background" tests `bg.alpha() == 0` — `Reset` is now a painted terminal default. (C11G-CANVAS-FILL)
- <a id="sc-selection-color"></a>**An author `::selection` color keeps the text's other color** (CSS Pseudo-Elements 4 §3.4, paired defaults): `::selection { background-color: yellow }` now paints the text's own color on yellow — the UA's white text applied too — and `::selection { color: red }` keeps the text's background. Set both to choose both. (C10G-SELECTION-PAIRED)
- <a id="sc-selection-properties"></a>**`::selection` keeps only the highlight properties** (CSS Pseudo-Elements 4 §3.2): `color`, `background-color`, the text decorations and custom properties; a `::selection { font-weight: bold }` that made selected text bold is dropped. (C10-HIGHLIGHT)
- <a id="sc-dashed-ends"></a>**A dashed or dotted side ends in its dash glyph** (CSS Backgrounds 3 §4.2): where no other side meets it — a box with no bottom border, a lone `border-left: dashed`, a top-only border — the side's first and last cells draw `╎` / `╌` (`┆` / `┄` dotted) like the rest of the run, where they drew the solid `│` / `─`; corners and junctions stay solid. (ACID-FIX-2)
- <a id="sc-glyph-overpaint"></a>**A glyph drawn over another shows in its own style** (CSS 2.1 Appendix E, CSS Color 4 §3): text, a border or an outline painted over an earlier glyph in a cell — over a negative-`z-index` pseudo-element, under a positioned box without a background — took the earlier glyph's colour when its own was the default, and kept its bold, italic and decorations; it now shows its own colour (the terminal default included), weight and decorations, over the background beneath. (ACID-FIX-3)
- <a id="sc-transparent"></a>**`transparent` is transparent black** (it was the terminal default color): `color: transparent` hides text. (C3-TRANSPARENT)
- <a id="sc-paint-phases"></a>**Overflowing text paints over what follows it** (CSS 2.1 Appendix E): a block's text running past it into a float or a later block now shows over the float's and the block's backgrounds (it was covered by them). (C8G-PAINT-PHASES)

### Selectors and the cascade

- <a id="sc-root-element"></a>**`:root` is the root fragment, styled and inherited from** (Selectors 4 §14.1, CSS Cascade 4 §7): `:root { color: …; line-height: … }` now reaches every element (only its custom properties did), `:root > .app`, `:root .x` and `:root:has(…)` match (they matched nothing), `rlh` and `scroll(root)` read the root (they read the first top-level element; `scroll(root)` is inactive, the root never scrolling), and `dom.node(dom.root()).computed()` is its style. A `:root` custom property inside `@media` / `@supports` / `<style media>` follows its condition — it applied unconditionally — and `Stylesheet::var()` / `vars()` no longer mirror `:root`: they hold only `define_var`'s variables; read a cascaded value from `computed().vars`. `*` and `*:hover` match the root too (they matched neither), so a universal rule styles the root fragment — and, through inheritance, everything under it — and `*:hover` matches it while the pointer is over the page. (C14G-ROOT-ELEMENT)
- <a id="sc-complex-selectors"></a>**Complex selectors match when any assignment of elements does** (Selectors 4 §3.1): `div > p span` matches a `span` whose nearest `p` is not the `div`'s child but a farther one is — the matcher took the nearest candidate per compound and gave up — so rules may start applying to elements they missed. (C11-COMBINATORS)
- <a id="sc-sibling-combinators"></a>**`+` and `~` skip text and comments** (Selectors 4 §14.3–§14.4): they relate element siblings, so `h1 + p` matches across the whitespace text node a parsed template puts between them, and a comment; it matched nothing there. (C11-COMBINATORS)
- <a id="sc-display-inline"></a>**`display: inline` resets the inner display type**: in one cascade `display: flex` then `display: inline` is `inline flow`, not an inline flex container. (C6-DISPLAY-KEYWORDS)
- <a id="sc-side-longhands"></a>**A side is a longhand**: `.a { margin-top: 1 } .a.b { margin-left: 2 }` keeps the top margin (it was reset to 0), and `!important` marks one side. (C6-MARGIN-SIDES)
- <a id="sc-border-shorthand"></a>**`border` resets color and width** (CSS Backgrounds 3 §4.4): `border: solid` after a `border-color` makes the sides `currentcolor`; and `border: rounded` is a `border-radius`, which a later `border` keeps. (C4-BORDER-SHORTHAND, C4-RADIUS)
- <a id="sc-ill-typed-math"></a>**Ill-typed math is invalid** (`calc(50% * 10%)` drops the declaration) and division by zero is IEEE-754 (CSS Values 4 §10.9). (C2-TRIG, C2G-CALC-SEMANTICS)
- <a id="sc-cssom-serialize"></a>**CSSOM reads back the shortest form, and kept values as written**: `padding: 1` (was `1 1 1 1`), `display: block` for `block flow`, `flex: 1` as `1 1 0%`, custom properties and `var()` declarations as written. (C5G-CUSTOM-SERIALIZE, C6-MARGIN-SIDES, C6-DISPLAY-KEYWORDS)
- <a id="sc-parentless-child"></a>**`:first-child` / `:last-child` / `:only-child` match an element without a parent** (Selectors 4 §13.3): a detached or root element matches them, as `:nth-child(1)` does. (C11-NTH)
- <a id="sc-scope-query"></a>**`:scope` in the query methods is the node queried** (DOM §4.2.6, Selectors 4 §14.3): `query_selector_in(root, ":scope > p")` is `root`'s own `p` children, and `matches` / `closest` scope to the element; `:scope` was `:root` there. (C11-SCOPE)

### Forms, dialogs and interactive elements

- <a id="sc-summary-weight"></a>**`<summary>` is no longer bold** (HTML §15.5.20): the UA gave it `font-weight: bold`; it now draws like the text around it, with its `▸` / `▾` marker. Keep the old look with `summary { font-weight: bold }`. (ACID-FIX-4)
- <a id="sc-dt-legend-weight"></a>**`<dt>` and `<legend>` are no longer bold** (HTML §15.3.3, §15.3.12): the UA gave them `font-weight: bold`; HTML gives `dt` only its block display and `legend` its block display and padding, so they now draw like the text around them. Keep the old look with `dt, legend { font-weight: bold }`. (ACID-FIX-6)
- <a id="sc-fieldset-disabled-text"></a>**A disabled `<fieldset>`'s legend and text keep their colour**: the UA greyed everything inside a `<fieldset disabled>` (its `:disabled` rule matched the fieldset and the colour inherited); now only the disabled controls are muted, as in browsers. Restore the old look with `fieldset:disabled { color: GrayText }`. (ACID-FIX-8)
- <a id="sc-backdrop-color"></a>**`::backdrop { color }` no longer recolors the page beneath a modal dialog**: rdom painted every glyph under the backdrop in its `color` — which the backdrop inherits from the dialog, so `dialog { color: … }` recolored the whole page. To dim the page, give the backdrop a translucent background (`::backdrop { background-color: rgb(0 0 0 / 50%) }`), which tints the glyphs beneath it. (ACID-FIX-13)
- <a id="sc-appearance-none"></a>**`appearance: none` strips a control's UA chrome** (CSS UI 4 §7.1): `appearance` and `-webkit-appearance` were dropped as unknown properties in 0.5; now `none` removes the UA's `::before` / `::after` chrome, so a reset's `button, select { appearance: none }` loses the `[ ` / ` ]` brackets and the `▾`, and `<progress>`, `<meter>` and a range slider draw no bar or track. The web's custom checkbox — `input[type=checkbox] { appearance: none; width: 1em; height: 1em; border: 1px solid }` — loses its `[x] ` mark, and with the font-relative `em` sizes dropped it is an empty 2×2 border box whose `:checked { background }` has no interior to paint. Port it in cells and draw the mark with `::before`: `input[type=checkbox] { appearance: none } input[type=checkbox]::before { content: '[ ] ' } input[type=checkbox]:checked::before { content: '[✓] ' }`. Remove an `appearance: none` that was there for a browser only. (C12-CONTROLS)
- <a id="sc-control-text"></a>**Form controls do not inherit the page's text properties** (HTML §15.5): `input`, `textarea`, `select` and `button` reset `line-height`, `text-transform`, `text-indent`, `text-align`, `letter-spacing`, `word-spacing` and the font's weight and style, so a `body { font-weight: bold }` no longer makes a field's text bold (buttons stay bold by their own UA rule). Set the property on the control to style its text. (C9G-UA-LINE-HEIGHT, C9G-LETTER-SPACING)
- <a id="sc-modal-dialog"></a>**A modal dialog is centred over the page, and the page under it is inert** (HTML §4.11.4, §6.3, CSS Position 4): `dialog::show_modal` puts the dialog in the top layer — centred in the viewport by the UA's `dialog:modal`, painted above everything, outside every `overflow` clip — where it sat in flow, so it now covers content; everything outside it, and an `[inert]` subtree (the attribute only reflected before), is skipped by Tab, `focus()` / `focus_node`, the pointer and text selection, a focused element made inert is blurred, and a dialog with nothing focusable takes the focus itself. Style `dialog:modal` to place it elsewhere. (C11-MODAL-POPOVER, C11G-MODAL-INERT)
- <a id="sc-select-overlay"></a>**An open `<select>` overlays the page** (HTML's select picker, CSS Position 4's top layer): its option list draws over the content below it — and outside an `overflow: hidden` ancestor — instead of growing the select and pushing that content down; a click outside closes it. (C12-SELECT-TOP-LAYER)
- <a id="sc-textarea-grip"></a>**A textarea's corner shows a grip and resizes it** (CSS UI 4 §4.2, HTML's UA `textarea { resize: both }`): its bottom-right cell inside the border draws `◢`, and a press there starts a resize drag (writing its `width` / `height` into its `style`) instead of reaching the textarea or its scrollbar. Set `textarea { resize: none }` to keep the old cell. (C12-CONTROLS, C12G-RESIZE-PICKER)
- <a id="sc-change-on-blur"></a>**Text fields fire `change` on blur** (HTML §4.10.5.5): a text-family `<input>` or `<textarea>` the user edited fires `change` before `blur` when it loses focus, and every builtin `change` first sets the control's user validity — a `change` listener that saved or validated now runs on every Tab out of an edited field (it never ran for text). (C11-FORM-STATES)
- <a id="sc-enter-commits"></a>**Enter commits a text field** (HTML §4.10.5.5, as browsers do): Enter in a single-line `<input>` fires `change` when the user edited it, before the form submits; and a form with no submit button holding a text field and a date / time field no longer submits on Enter (both block implicit submission, §4.10.21.2). (C11G-ENTER-COMMIT)
- <a id="sc-details-boxes"></a>**A `<details>` lays out its summary and one content box** (HTML §15.5.20): its content — every child but the first `<summary>` — is laid out inside the `::details-content` box, after the summary wherever the summary is among the children. A `details { display: flex }` has two flex items, the summary and that box (each child was one); loose text in an open `<details>` takes the slot's style; a percentage inside resolves against the box (the same width unless the slot is styled). Style the content's layout on `details::details-content`. (C10G-DETAILS-CONTENT-BOX)
- <a id="sc-details-closed"></a>**A closed `<details>` hides all its content, text included** (HTML §15.5.20): text placed directly inside a closed `<details>`, beside its `<summary>`, is hidden with the rest — it showed, as the UA hid only element children. Wrap text that must stay visible in the `<summary>`. (C10-DETAILS-CONTENT)
- <a id="sc-details-display"></a>**A closed `<details>`'s content computes its own `display`** (HTML §15.5.20, CSS Containment 2 §4): it computed `none`; the closed slot is now `content-visibility: hidden`, which skips the content and leaves its styles alone — code that read `display == None` to find closed content reads the `<details>`'s `open` instead; the content is still neither painted, hit nor focusable. (C14-CONTAIN)
- <a id="sc-modal-popovers"></a>**`showModal()` hides open popovers** (HTML §4.11.4): showing a modal dialog hides every open auto and hint popover (with `beforetoggle` / `toggle`), and Esc closes the most recent of the modal dialogs and popovers. (C11-MODAL-POPOVER)
- <a id="sc-dialog-show-focus"></a>**`dialog::show()` focuses into the dialog** (HTML §4.11.4 `show()` steps 10–16, as `showModal()` already did): it runs the dialog focusing steps — the `[autofocus]` element, else the first focusable one, else the dialog — remembers the previous focus for `close()`, and hides the auto popovers not holding it. (C11G-POPOVER-BOUND)
- <a id="sc-dialog-beforetoggle"></a>**A `<dialog>` fires `beforetoggle`** (HTML §4.11.4, current Living Standard): `show()` / `showModal()` fire a cancelable `beforetoggle` (`closed` → `open`) before opening — canceled, the dialog stays closed — and `close()` a non-cancelable one (`open` → `closed`); the dialog's `toggle` is no longer cancelable. (C11G-DIALOG-BEFORETOGGLE)
- <a id="sc-indeterminate"></a>**An indeterminate checkbox draws `[-]`** (HTML §4.10.5.1.15): a checkbox with its indeterminate flag (the `indeterminate` attribute) shows `[-] ` instead of `[x] ` / `[ ] `; override `input[type=checkbox]:indeterminate::before`. (C11-FORM-STATES)

### Transitions and animations

- <a id="sc-transition-computed"></a>**A running transition is the computed value** (CSS Transitions 1 §3, Web Animations 1 §5.4.5): layout, paint and inheritance read it, so a `width` / `height` / `padding` / `margin` / inset / `gap` transition grows the box frame by frame (layout took the end value at once), descendants inherit a running `color` — `computed()` holds the running values, `base_computed()` the cascade's style without them — and `transition: all` covers every animatable longhand — `opacity`, margins, `min-*` / `max-*`, fonts, text spacing, … Events fire per longhand (`padding` → `padding-top` …); a pair that does not interpolate (`auto` → `10`, `gap: normal` → `2`, a keyword) changes at once and fires nothing (it ran and stepped); the last `transition-property` entry naming a property wins. (C12-ANIMATABLE)
- <a id="sc-starting-hidden"></a>**A newly rendered element does not transition from its hidden values** (CSS Transitions 1 §3): coming out of `display: none` (itself or under an ancestor), it has no before-change style, so its values change at once — it transitioned from the values it had while hidden. Give it a `@starting-style` to fade it in. (C12-STARTING)
- <a id="sc-reversed-transition"></a>**A reversed transition is shortened, and `transitioncancel` reports the active time** (CSS Transitions 1 §3, §6.1): a change back to a running transition's start value (a hover leaving half-way) now runs back over the share it had covered instead of the whole `transition-duration`, and a cancel's `elapsedTime` no longer counts the delay. (C12G-MISC)
- <a id="sc-animation"></a>**`animation` declarations run** (CSS Animations 1 §3–§4): `@keyframes` rules and the `animation-*` properties were dropped with warnings in 0.5; a sheet's `animation: spin 1s infinite` now animates the element on the app's clock and fires `animationstart` / `animationend`, and its `@keyframes` no longer warns. Remove a declaration that was there for a browser only. (C12-KEYFRAMES)
- <a id="sc-timing"></a>**Negative `transition-delay`, `linear()` easings and `@starting-style` apply** (CSS Transitions 1 §2.4, CSS Easing 2 §2.1, CSS Transitions 2 §3): each was dropped in 0.5 — the declaration, or the whole at-rule, with a warning — so a browser sheet's `transition-delay: -100ms` now starts its transition part-way through, `linear(0, 0.25 75%, 1)` follows its stops (the declaration was lost and the previous easing applied), and a `@starting-style { .toast { opacity: 0 } }` block makes a newly shown element transition from it. (C12-TIMING, C12-STARTING)
- <a id="sc-animation-events-first"></a>**Transition and animation events fire before the frame they happen in is drawn** (HTML §8.1.7.3 "update animations and send events"): a `transitionstart`, `transitionend` or `animationend` listener's change — removing a toast, swapping a class — used to show one frame late, after a frame with the old content; it is now in that frame. A listener that read layout sees the previous frame's, as in a browser. (ACID-FIX-15)
- <a id="sc-detached-animations"></a>**A removed element's transitions and animations are cancelled** (CSS Transitions 1 §3, CSS Animations 1 §4.1): `remove_child` fires `transitioncancel` / `animationcancel` for what runs in the subtree (a transition ran on to `transitionend`), and an element inserted again has no before-change style, so it takes its values at once and restarts its animations. (C12G-DETACHED)

### Conditional rules and containment

- <a id="sc-conditional-rules"></a>**`@media`, `@supports` and `@container` rules apply** (CSS Conditional 3 §3, §6, Conditional 5 §6.4, Media Queries 4): they were dropped with a warning in 0.5; an `@supports` block now applies when rdom parses what it asks (C14-SUPPORTS), an `@container` block while its container's size or custom properties match (C14-CONTAINER); a block now applies while its query matches the terminal — `screen`, `width` / `height` in cells, `hover`, `prefers-color-scheme` — and an `@import` media list or a `<style media>` attribute conditions its sheet (`<style media="print">` no longer applies). The scheme is dark unless the terminal reports a light background, so a shared web sheet's `@media (prefers-color-scheme: dark)` blocks now apply on most terminals, and its `@media screen` blocks always. A pixel or `em` breakpoint selects at 8px a column and 16px a row (`min-width: 768px` from 96 columns; C14G-PX-BREAKPOINTS) — a browser sheet's mobile-first rules turn on at real terminal widths. A headless cascade (`CascadeExt::cascade`, no `App`) whose document never had a viewport — no `set_viewport`, no layout — leaves the size features (`width`, `height`, `aspect-ratio`, `orientation`) unknown, so neither a size query nor its `not` applies until `dom.set_viewport(Viewport::new(w, h))` (C14G-CONDITIONAL-SPEC). (C14-MEDIA)
- <a id="sc-container-type"></a>**`container-type: inline-size` / `size` contain the box's size** (CSS Containment 2 §3.1): the properties were dropped as unknown in 0.5; a query container now sizes as if empty on its contained axes — a floated, inline-block or flex-item card with `container-type: inline-size` and no width shrinks to its padding; give it a width or `contain-intrinsic-width`. (C14-CONTAINER)
- <a id="sc-containment"></a>**`contain`, `content-visibility` and `will-change` take effect** (CSS Containment 2 §3–§4, CSS Will Change 1 §3): they were dropped as unknown properties in 0.5; `content-visibility: hidden` now skips the contents (`auto` while off-screen); `contain: paint` (and `content`, `strict`) now clips the content to the padding box, layout and paint containment contain floats, margins and positioned boxes and stack, `will-change: opacity` / `transform` stack, and `will-change: transform` contains positioned descendants — a `position: fixed` descendant is now placed in (and scrolls with) a `will-change: transform` ancestor, not the viewport. (C14-CONTAIN)

### Effects: transforms, filters, blending and clipping

- <a id="sc-layer-default-colours"></a>**Default-coloured text inside a clip path, a filter's or blend mode's element, or an isolated group keeps the terminal's colours**: the layer those paint through wrote their default (`reset`, `CanvasText` / `Canvas`) cells back as explicit white on black; a light-themed terminal now shows them in its own colours. (ACID-FIX-9)
- <a id="sc-transforms"></a>**`transform` and `translate` take effect** (CSS Transforms 1 / 2): they were dropped as unknown properties in 0.5; a browser sheet's `transform: translate(-50%, -50%)` now moves the box by whole cells — its paint, hit-testing and scrollable overflow — and any transform, `rotate(45deg)` too (which draws nothing), makes the box a stacking context and the containing block of its fixed and absolute descendants. Drop the transform where the move is unwanted. (C15-TRANSLATE)
- <a id="sc-legacy-clip"></a>**Visually-hidden text is hidden** (CSS 2.1 §11.1.2): `clip: rect(0, 0, 0, 0)` on an absolutely positioned box — Tailwind v3's `sr-only`, Bootstrap's `.visually-hidden` — now clips it to nothing, where `clip` was dropped and the screen-reader text showed on the page; such a box is also a stacking context. (C15G-LEGACY-CLIP)
- <a id="sc-filters"></a>**`filter` and `backdrop-filter` take effect** (Filter Effects 1 / 2): they were dropped as unknown properties in 0.5; a browser sheet's `filter: grayscale(1)` or `backdrop-filter: brightness(0.5)` now recolors what the element paints (or what lies behind it), and any filter — `blur()` too, which draws nothing — makes the box a stacking context and the containing block of its positioned descendants. (C15-FILTER)
- <a id="sc-blending"></a>**`mix-blend-mode` and `isolation` take effect** (Compositing and Blending 1): they were dropped as unknown properties in 0.5; a sheet's `mix-blend-mode: multiply` now blends what the element paints with what lies beneath it, and either property (other than `normal` / `auto`) makes the box a stacking context. (C15-BLEND)
- <a id="sc-clip-path"></a>**`clip-path` takes effect** (CSS Masking 1 §5): it was dropped as an unknown property in 0.5; a sheet's `clip-path: inset(…)`, `circle()`, `ellipse()` or `polygon()` now hides the element's (and its descendants') cells outside the shape and stops pointer events there, and any `clip-path` makes the box a stacking context. Tailwind v4's `sr-only` (`clip-path: inset(50%)`) now hides its text, as in a browser. (C15-CLIP-PATH)

### Runtime and API readers

- <a id="sc-canvas-hit"></a>**A point on the canvas hits the root** (CSSOM View §5, UI Events): outside every box, `hit_test` / `hit_test_path` / `element_from_point` return the root (`dom.root()`, `[root]`) where they returned nothing — a click on the empty screen dispatches at the root, moving there is a `mouseout` / `mouseover` onto the root (`hovered()` is the root, not `None`), and a press there starts a selection snapped to the nearest text. Code that read `None` as "on nothing" compares with `dom.root()`. (C14G-ROOT-ELEMENT)
- <a id="sc-focus-scroll"></a>**Focusing an element scrolls it into view** (HTML's focusing steps): Tab, Shift+Tab and `focus()` move every scroll container around the newly focused element to reveal it (`nearest`, within its `scroll-padding`) — under an `App` at the next layout — so a scroller's offset, and an app's snapshots, change on focus. Pointer focus does not scroll; `focus_with(FocusOptions::new().prevent_scroll(true))` focuses without scrolling. (C8-SCROLL-PADDING, C8G-FOCUS-SCROLL)
- <a id="sc-focus-hidden"></a>**`focus()` refuses a hidden element** (HTML §6.6.2: a focusable area is being rendered): `focus()`, Tab, `is_focusable` and `tab_index` skip an element that is — or is inside — `display: none`, or whose `visibility` is not `visible`, and a focused element that becomes hidden is blurred. Under an `App`, `focus()` flushes the element's pending style first, as a browser does, so a handler that shows a panel and focuses its input in one call focuses it. (C6G-VISIBILITY-ONE-ANSWER, C12-FOCUS-FLUSH)
- <a id="sc-move-record"></a>**Moving an element is a removal and an insertion** (DOM §4.2.3): `append_child` / `insert_before` of an attached element now fires its old parent's `childList` removal record before the insertion's, so an observer sees the move, and under an `App` the moved element's transitions and animations are cancelled and restart, as browsers restart CSS animations on a DOM move; `replace_child`'s record names the replaced child. (C12G-MOVE-RECORD)
- <a id="sc-modifiers"></a>**`ComputedStyle::modifiers` no longer carries the decorations**: the cascade sets only bold and italic there (from the font); an underline or line-through is in `computed.applied_decorations` (`underline` / `overline` / `line_through`, each an `Option<AppliedLine>` with its style and color, and `blink`), propagated from the decorating ancestors. `computed.modifiers.contains(Modifier::UNDERLINED)` still compiles and is now always false — test `computed.applied_decorations.underline.is_some()` instead. (C9-DECORATION)
- <a id="sc-rendered-text"></a>**Layout readers see the rendered text**: `InlineFragment::text` is what layout draws — transformed text, a tab's cells, justification spaces, a soft hyphen's `-`, letter spacing — not the source; `InlineFragment::source_len()` is the source bytes it covers (use it, not `text.len()`, to map back into the text node). `LineBox::text_row()` is the line's baseline row, no longer every run's: a run `vertical-align` moved is at `line.top + fragment.y`. (C9-BREAKING, C9-TEXT-TRANSFORM, C9-TAB-SIZE, C9-TEXT-ALIGN, C9-VERTICAL-ALIGN)
- <a id="sc-removed-style"></a>**A removed element keeps no style, and `AnimationRegistry::needs_frames` means a frame is due now**: an element taken out of the document (and not inserted again before the next frame) reads `computed` `None`, as `getComputedStyle` reads nothing there, and is styled afresh when inserted (C12G-DETACHED); `needs_frames` is `false` between a stepped animation's steps and for an animation of nothing rdom renders. (C12G-FRAME-COST)
- <a id="sc-signed-scroll"></a>**Scroll offsets are signed**: `scroll_x` / `scroll_y` are negative in a scrolled `rtl` box and under `row-reverse`, `column-reverse` and `wrap-reverse` (CSSOM View §4); `TuiAccessors::scroll_range()` gives the legal values. (C5G-RTL-SCROLL, C6-DIRECTION-REVERSE, C6G-SCROLL-API)
- <a id="sc-cursor"></a>**The pointer changes shape over the page** (CSS UI 4 §4.1): in kitty, foot, WezTerm and Ghostty an `App` now sets the terminal pointer — the text pointer over text, `pointer` over links, a sheet's `cursor` elsewhere — where it was left alone. `App::with_pointer_shapes(PointerShapes::None)` keeps the terminal's own. (C12-CURSOR)
- <a id="sc-virtual-screen-osc"></a>**`VirtualScreen` reads OSC strings** (ECMA-48 §8.3.89; `test-util`): a test that replays an `App`'s output no longer sees an `<a href>`'s OSC 8 hyperlink as the text `8;;URI` in its rows — the rows read as the terminal shows them, and each link cell's `Cell::link` holds its URI. A snapshot recorded with the escape text in it changes. (ACID-FIX-1)
- <a id="sc-resize-rearm"></a>**An `App` built `with_backend` no longer writes the mouse-capture modes to stdout on a resize**: every `App` re-armed mouse tracking on process stdout at each resize event, whatever its backend — a headless or test app printed the sequences into the program's output. Only the `App` that entered TUI mode on stdout (`App::new`) re-arms it now. A program that sets up its own crossterm terminal and passes it `with_backend` re-arms in a `resize` listener: `rdom_tui::render::backend_crossterm::enter_mouse_capture(&mut std::io::stdout())`. (ACID-FIX-16)
- <a id="sc-dom-convenience"></a>**`append` / `prepend` / `before` / `after` / `replace_with` / `replace_children` follow DOM §4.2.6**: they check every node before any moves (an invalid one used to leave a partial insert, or an emptied parent for `replace_children`); `replace_with([self])` keeps the node; a sibling or first child in the list moves with the rest, in list order. (C13G-DOM-CONVENIENCE)

## Compile breaks

What a 0.5 consumer must change to compile, by kind. Each kind names the `crates/rdom-tui/tests/integration/migration_hints.rs` tests that compile its new form with `use rdom_tui::*;` alone; the [API changes table](#api-changes-from-05) has every item.

- **Sealed traits**: rdom-tui's extension traits (`CascadeExt`, `LayoutExt`, `PaintExt`, `HitTestExt`, …) are call-only. — `sealed_trait_hints`

- **Typed values**: `MinSize` / `MaxSize` for `min-*` / `max-*`, `f32` flex factors, `i64` integer tokens, `i32` scroll offsets and `z-index`, `AspectRatio` behind accessors, `row_gap` / `column_gap`, `FlexBasis`. — `sizing_hints`, `calc_payload_hints`, `gap_hints`, `flex_longhand_hints`, `scroll_token_and_line_hints`, `reverse_and_signed_scroll_top_hints`, `z_index_hints`

- **New fields on style records**: build `TuiStyle` / `ComputedStyle` with `TuiStyle::new()` / `ComputedStyle::initial()`; a destructuring pattern adds `..`; the `transition-*` fields moved into the `motion` group (`c.motion.transition_duration`). — `cascade_hints`, `box_model_hints`, `display_keyword_hints`, `multicol_and_anchor_hints`, `grid_and_motion_group_hints`
- **Layout records are `#[non_exhaustive]`**: `LineBox`, `InlineFragment`, `GeneratedFragment` and `AnonymousIfc` are built by constructor; a line is found by `InlineLayout::line_at_row(row)`, not `lines[row]`. — `line_box_construction_hints`, `generated_fragment_construction_hints`, `anonymous_box_hints`, `scroll_token_and_line_hints`

- **Pseudo-element reads are accessors**: `TuiExt`'s pseudo-element style fields are methods of the same names (`ext.computed_backdrop()`), and positioned `::before` / `::after` are read through `positioned_pseudos()`. — `tui_ext_pseudo_hints`, `generated_box_read_hints`
- **Text decorations and fonts are groups**: `TuiStyle::text_decoration` is `TextDecorationDeclarations`, the `bold` / `italic` fields are `TuiStyle::font` (`FontDeclarations`; the builders are unchanged), and `render::Style` / `SgrState` gain `underline_color`. — `text_decoration_hints`, `font_hints`
- **Tables are laid out, not sized by helpers**: `size_all_tables` / `size_columns` / `table_used_width` are gone; read `node.table_tracks()`. — `table_layout_hints`
- **Removed helpers**: `parse_unsigned`, `round_half_to_even`, `Content::Attr`, `animation::effective_*`. — `token_and_math_hints`, `content_hints`, `animation_api_hygiene_hints`
- **Dialog methods return `Result`**: `dialog::show` / `show_modal` (`?` them). — `dialog_show_hints`
- **Transitions**: `transition-property` names any property (`TransitionProperty::named("color")`, a `Named(PropertyName)` for a known one); `TimingFunction` is `#[non_exhaustive]`; the engine's `AnimatedProp` / `AnimatedValue` and `PresentationStyle`'s value fields are gone — read the running value from `computed`. — `transition_property_hints`, `timing_hints`, `animation_api_hygiene_hints`
- **App configuration is consuming**: `with_tick_rate`, `with_tick_handler`, `with_animation_frame_rate`, chained after the constructor. — `app_config_hints`
- **Selectors**: `SimpleSelector::Attribute` gains `case: AttrCase` (build it with `case: AttrCase::Default`; match `{ name, op, value, .. }`). — `selector_hints`
- **Render records**: `Buffer` is built by `Buffer::empty` / `filled` / `with_cells`. — `render_hints`
