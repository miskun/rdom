- **`PARTIAL-RELAYOUT-1` — no layout pass re-lays out only what changed (post-0.6).** `layout_dom` is a whole-tree pass: a style or text change, a running geometry transition or animation (`ANIM-RELAYOUT-1`) and a resize lay the whole document out, multi-column balancing and anchor fallbacks included. A scroll no longer does (C15G-SCROLL-NO-RELAYOUT: the scrolled boxes are moved, `layout_pass::scroll_update`). The pay-down is a pass that re-lays out the dirty subtrees and what their size changes reach — the subtree boundaries `contain: layout` / size containment already mark (CSS Containment 2 §3) and the translation invariance the scroll update relies on. Named by the Phase 15 gate (architect, program health); scheduled after 0.6.

- **`HIT-OVERFLOW-1` — content overflowing a non-clipping box is hit only inside that box.** CSS hit-tests what paints where it paints (CSSOM View §5 `elementFromPoint`, CSS 2.1 Appendix E): text overflowing an `overflow: visible` block, or a child box overflowing its parent, is a target where it is drawn. rdom's hit test enters a box only when the point is inside its border box (`runtime::hit_test::descend::descend_plain`, `box_contains`), so a click on such overflow lands on what is beneath it (found while building acid part 1; recorded in DIVERGENCES §4 by ACID-TILES-B, 2026-10-10). The pay-down: descend into a box that does not clip its overflow wherever the point is, which needs the inline hit to tell "on the block's own text" from "on nothing" (`inline_hit::hit_lines` answers both with `false`) and loses the border-box prune a hit test leans on — a per-box ink-overflow rect, or the scrollable-overflow rect layout already computes for scroll containers, would restore it. Acid step I24 pins today's behaviour (tile 53's overflowing text over a float hits the float); paying this down turns that checkpoint over.

## Accepted simplifications

A review-gate finding accepted as a risk is recorded here until it is paid down; a choice that is permanent goes to the [`DESIGN.md` decision archive](DESIGN.md#decision-archive) instead (`D-M1-1` moved there in 0.5.0).

- **`HAS-COST-1` — `:has()` invalidation restyles an anchor's whole subtree.** C11-HAS restyles only the elements a cascade flagged as anchors (`TuiExt::has_anchor`), with no work at all without a `:has()` rule. But a restyle in rdom is a subtree's (the dirty tracker's granularity), so a `body:has(.error)` anchor restyles the document when its answer may have changed — Blink restyles the anchor alone and its descendants only if an inherited value moved. The flag is sticky (an element that stops being an anchor keeps it until it is dropped: one spare restyle per relevant change). The bounds (C11G-HAS-COST, each pinned by a counting test): *matching* — an argument of descendant and child combinators only (`:has(.x)`, `:has(> li)`, `:has(p div)`) is answered once per (element, compound) per pass, O(N · compounds) over nested anchors; an argument with a sibling combinator searches each anchor's later siblings (and their subtrees when it steps down) once per pass, each candidate's chain read back no farther than the anchor — O(siblings · subtree) per anchor, so `:has(~ …)` over a long list is quadratic in a pass; combinators backtrack in O(depth) per compound (Servo's outcomes). *Invalidation* — a change walks its ancestors and, per sibling list, at most as many earlier siblings as a leading `+` run reaches (all of them with `~` or a sibling step nested in `:is()` / `:not()`), each (element, parent) once per drain: O(depth + reach) per change, and a drain's `~` walks of one list are linear in it. An anchor *after* the changed element — reachable only through a sibling step nested in an argument (`.a:has(+ :is(.x ~ *))`) — is restyled by the sibling marking instead (every sibling of the changed element, once per parent per drain: O(siblings); C11G-HAS-IS-SIBLING). Pay down with an element-only restyle mode in `cascade_subtrees` (keep the subtree when the anchor's computed style is unchanged, as `Mode::Restyle` does) and a later-sibling memo for `~`.
- **`TIMELINE-SCOPE-COST-1` — a named timeline behind `timeline-scope` is looked up per frame through the scope's subtree.** C12-SCROLL-DRIVEN resolves an animation's named timeline each frame it steps (a name can move to another element without the animated element's style changing): the walk climbs its ancestors and, at an ancestor whose `timeline-scope` takes the name, searches that ancestor's subtree for the elements declaring it — O(subtree) per scroll-driven animation per frame. Frames step scroll-driven animations only when something ran (a scroll, a layout), and `timeline-scope` is rare. Pay down with a per-cascade map of declared timeline names, rebuilt when a cascade changes a timeline property.
- **`SCOPE-MEMO-1` — `@scope` memo memory is O(N × depth) per scope in one cascade pass.** `ScopeMemo` (`rdom-tui/src/style/cascade/scope.rs`, `C1G-SCOPE-COST`) keeps, per (sheet, `@scope`, node) the scoping roots that have the node in scope, with their generations, so each root and limit test runs once per pass. A node's list extends its parent's one generation farther, so it is a fresh `Rc<[(NodeId, u32)]>` per node: the bound is, per `@scope` rule set, the number of nodes the scoped rules are tested against times the number of scoping roots above each — at most N × depth entries of 12 bytes (a 5 000-node tree 20 deep with a root at every level: 100 000 entries, 1.2 MB, plus an `Rc` header and a map slot per node), freed when the pass ends (the memo lives in the pass's `Scratch`). Accepted at the Phase 2 gate: real `@scope` roots are few (components, not every level), so the lists are short; sharing a parent's list (generations stored relative to the parent) would make it O(N) but costs an extra walk per proximity read. Revisit if a profile shows the memo.

- **`CONTAINER-TRANSITION-1` — a frame's cascade and its container re-cascade are two style change events.** An element dirty-cascaded and re-cascaded by a container pass in one frame diffs B → C in the layout hook against the intermediate B the main hook left as its before-change style, so a property whose `transition` only C's rule adds starts from the never-painted B, and one C returns to A runs a reversed transition with events (DIVERGENCES §2's container entry). Paid down by the layout hook diffing against the frame's first before-change style (A) and §3's end-value comparison for the transitions the main hook started this frame. Found as batch A's open point (C14G-CONTAINER-FIDELITY); recorded by C14G-DOCS.
- **`ANIM-RELAYOUT-1` — a running geometry transition or animation lays the whole page out on the frames it moves a value.** A scroll no longer does (C15G-SCROLL-NO-RELAYOUT, 2026-10-09): a wheel tick in a 2000-row document laid out 4 003 boxes in one run of phases 1–2 and now lays out none — the scrolled boxes are moved and the sticky, anchored and static-position boxes placed again (`layout_pass::scroll_update`; `runtime::app::scroll_cost_tests`, `scroll_update::tests::a_scroll_lays_nothing_out`), a layout only where the move could differ from one (a box placed again at another size, a `content-visibility: auto` relevance change). C12-ANIMATABLE composites a running transition's value onto the element's computed style, so layout reads it; `layout_dom` is a whole-tree pass (there is no partial relayout). Since C12G-FRAME-COST a frame lays out only when the composited value of a longhand layout reads (`Longhand::affects_layout`: anything but the colors, `opacity`, the shadows, the outline, the caret and the cursor) differs from the previous frame's — a whole-cell `height` animation lays out on the frames its value moves, a stepped `visibility` blink at its flips; a stepped animation (every keyframe interval `steps()`) or a `steps()` transition wakes the App only at its steps (C12G-CARRYOVER for the transition), and one with an empty effect (`transform` until Phase 15) asks for no frames, its events serviced at their times without a frame. A page with none running pays nothing; the transition hook visits only the subtrees the cascade recomputed. The bound, counted in runs of layout's phases 1–2 (`layout_pass::ROUNDS`): a frame lays out at most twice — the layout, then one relayout when the scroll-driven timelines' re-step (Scroll-driven Animations 1 §5) moved a value layout reads or a scroll update must fall back; the re-snap, the focus scroll and the caret reveal alone move the scrolled boxes without one (`layout_pass::scroll_update`, C15G-SCROLL-NO-RELAYOUT) — each followed, when its container passes re-cascaded something whose new transition moves a value layout reads, by one more (the in-frame transition hook, C14G-CONTAINER-FIDELITY: four at most, only in a frame where a query flips under a geometry transition) — each `layout_dom` at most two passes with a `calc-size()`d box (`layout_pass::calc_size`) — `d + 2` when such boxes nest `d` deep, resolved inside out (C12G-CARRYOVER); a level takes its pass only when a box in it changes size, so the extra passes are paid while a sum moves a size (a running `interpolate-size` transition) and an authored identity sum at rest (`calc-size(auto, size)`, Chrome's accordion) costs none (C13G-CALC-SIZE-AUTHORED) — of at most `MAX_ROUNDS` (3) rounds while positioned boxes change their scrollers' reach — and each `layout_dom` is up to 1 + `container_pass::MAX_PASSES` (8) such layouts while query containers' sizes move or `content-visibility: auto` elements change relevance (C14-CONTAINER, C14-CONTAIN), each pass after the first re-cascading the moved containers' subtrees: so a frame is at most 4 `layout_dom`s × 9 layouts = 36 layouts, and 4 × 9 × 2 × 3 = 216 phase runs with a moving `calc-size()` box and no nesting, 108 without one, 4 × 9 × (d + 2) × 3 with nesting, plus up to 32 subtree cascades, all doubled when a drag autoscroll tick runs its off-frame `cascade_and_layout` before the frame (C12 left it at 3 × 2 × 3 = 18 and 36; before the container factor, C14G-CONTAINER-LOOP, it read 12; C14G-CONTAINER-LOOP's 2 × 9 × 2 × 3 = 108 left out the hook's two relayouts, C14G-COST-PINS). The container factor is paid only while a size moves: a container no cascade reads is forgotten, one cycling against its own scrollbar is frozen, and a run that reaches the cap asks for no further frame. The `calc-size()` pass and its collecting walk stop once no box is `calc-size()`d (the flag clears). Pinned by `runtime::app::frame_cost_tests` (`a_frame_runs_at_most_two_layouts`: 4 runs for a frame needing a focus scroll, a re-step and a `calc-size()` box; `a_frame_with_a_focus_scroll_runs_three_layouts_of_the_container_cap`: 27 layouts — 3 `layout_dom`s of 9; 36 before the focus scroll became a scroll update — for a resize moving 40 nested containers whose re-cascaded levels flip a `step-end` geometry transition, with a focus scroll; `a_stepped_blink_wakes_only_at_its_flips`; `layout_follows_a_changed_value_not_an_animated_longhand`) and `animation_event_tests::an_infinite_animation_costs_a_composite_per_frame_and_layout_only_for_geometry`. Paid down by a layout pass that re-lays out only the dirty subtrees and what their size changes reach.

- **`SCROLL-UPDATE-1` — what a scroll still costs, and when it lays out** (C15G-SCROLL-NO-RELAYOUT). A scroll update walks the box tree once to find the scroll containers whose offsets moved (as the `App`'s moved-since-paint check does), moves each one's scrolled content (`O(subtree)`), places every anchor-positioned box again and every box whose static position moved under a containing block that did not, and runs the sticky, picker and pseudo-element offsets again — no box is laid out. It lays out instead (exactly, through `layout_dom`) when a box placed again changes size (an anchored box whose fallback or shrink-to-fit width changes with the scroll), when positioned boxes then reach further into their scroll containers, when a `content-visibility: auto` element changes relevance, or when an offset sits on a box that is not a scroll container. Accepted: those are the cases where a browser lays out too.
- **`STYLE-SHARED-1` — the copies a shared style group still makes** (C15G-STYLE-SIZE). An element that writes a field of a shared group (`effects`, `multicol`, `anchor`, `ui`, `grid`, `motion`) copies the group once per cascade; a child of a parent that set both an inherited UI property (`cursor`, `accent-color`, the caret's) and a non-inherited one (an outline, `appearance`, `resize`) copies the UI group to inherit; and a grid container that declares track lists, or an element with view-timeline insets or animation ranges, has its group copied by `resolve_context_units` to check for context units (written back only when one moved). Pinned by `cost_tests::the_rare_style_groups_are_shared_until_written`.
- **`PHASE15-APPROX-1` — Phase 15's terminal approximations live in DIVERGENCES.** The transforms, filters and compositing, clip paths, multi-column and fragmentation, and anchor positioning that Phase 15 shipped are laid out and painted in whole cells; each approximation is a deliberate, documented divergence, not debt to pay down: [`DIVERGENCES.md`](DIVERGENCES.md)'s entries "A transform moves a box by whole cells" (C15-TRANSLATE), "A filter maps the colors of the cells its element paints" (C15-FILTER; a translucent paint blends before the filter maps it, C15G-FILTER-COVERAGE), "A blend mode blends the colors of the cells its element paints with the backdrop's background" (C15-BLEND), "A clip path clips whole cells" (C15-CLIP-PATH), "Multi-column layout is laid out in whole cells, with six simplifications" (C15-COLUMNS, C15G-FRAGMENT-GAPS, C15G-MULTICOL-COST) and "Anchor positioning is laid out in whole cells, with four simplifications" (C15-ANCHOR, C15G-TRY-ORDER). The costs the Phase 15 gate found (architect N7, N8, N10, N11) were paid down in its batch A (C15G-ANCHOR-COST, C15G-MULTICOL-COST); a full layout per scroll, the largest, by C15G-SCROLL-NO-RELAYOUT.

## How to use this file

- **Adding an item.** ID format: `D-Mn-N` for milestone-specific deviations (where Mn is the milestone the work shipped in), `DRY-N` for refactor opportunities, `SUB-N` for substrate gaps, `OPS-N` for infrastructure, `M5-*` / `OPACITY-*` / `FOCUS-*` for topical groups.
- **Referring to an item.** Use the ID — `D-M2-2` etc. — in commit messages and PR descriptions.
- **Retiring an item.** Delete it. The historical context lives in the commit that retired it (`git log -S "D-M2-2"`).
