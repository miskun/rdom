- **`FOCUS-FLUSH-1` — `focus()` reads the last cascade's styles** (DIVERGENCES §2 "Focusability reads the last cascade's styles"). A browser's `focus()` flushes style first, so "show the panel, focus its input" in one handler works; rdom refuses the focus until the next frame has cascaded. The flush needs the cascade's inputs — the `App`'s author sheets with its `<style>` and `@property` sheets (`FramePrelude::cascade_order`), the `AnimationRegistry` (a flushed style change must start its transitions, or the frame's own diff misses it) and the `DirtyTracker`'s roots (what to cascade, and to drain so the frame does not repeat it) — all `App` state a handler's `&mut Dom` cannot reach. Paying it down means moving that style engine state behind the document (document data, as the property registry already is) so `focus()` can run the subtree cascade the frame would. `showModal()`'s `is_focusable_in_opened` is the one narrow substitute. Found by the Phase 7 API gate; scoped out of C7G-FOCUS-FIXUP.

## Accepted simplifications

A review-gate finding accepted as a risk is recorded here until it is paid down; a choice that is permanent goes to the [`DESIGN.md` decision archive](DESIGN.md#decision-archive) instead (`D-M1-1` moved there in 0.5.0).

- **`HAS-COST-1` — `:has()` invalidation restyles an anchor's whole subtree.** C11-HAS restyles only the elements a cascade flagged as anchors (`TuiExt::has_anchor`), with no work at all without a `:has()` rule. But a restyle in rdom is a subtree's (the dirty tracker's granularity), so a `body:has(.error)` anchor restyles the document when its answer may have changed — Blink restyles the anchor alone and its descendants only if an inherited value moved. The flag is sticky (an element that stops being an anchor keeps it until it is dropped: one spare restyle per relevant change). The bounds (C11G-HAS-COST, each pinned by a counting test): *matching* — an argument of descendant and child combinators only (`:has(.x)`, `:has(> li)`, `:has(p div)`) is answered once per (element, compound) per pass, O(N · compounds) over nested anchors; an argument with a sibling combinator searches each anchor's later siblings (and their subtrees when it steps down) once per pass, each candidate's chain read back no farther than the anchor — O(siblings · subtree) per anchor, so `:has(~ …)` over a long list is quadratic in a pass; combinators backtrack in O(depth) per compound (Servo's outcomes). *Invalidation* — a change walks its ancestors and, per sibling list, at most as many earlier siblings as a leading `+` run reaches (all of them with `~` or a sibling step nested in `:is()` / `:not()`), each (element, parent) once per drain: O(depth + reach) per change, and a drain's `~` walks of one list are linear in it. An anchor *after* the changed element — reachable only through a sibling step nested in an argument (`.a:has(+ :is(.x ~ *))`) — is restyled by the sibling marking instead (every sibling of the changed element, once per parent per drain: O(siblings); C11G-HAS-IS-SIBLING). Pay down with an element-only restyle mode in `cascade_subtrees` (keep the subtree when the anchor's computed style is unchanged, as `Mode::Restyle` does) and a later-sibling memo for `~`.
- **`SCOPE-MEMO-1` — `@scope` memo memory is O(N × depth) per scope in one cascade pass.** `ScopeMemo` (`rdom-tui/src/style/cascade/scope.rs`, `C1G-SCOPE-COST`) keeps, per (sheet, `@scope`, node) the scoping roots that have the node in scope, with their generations, so each root and limit test runs once per pass. A node's list extends its parent's one generation farther, so it is a fresh `Rc<[(NodeId, u32)]>` per node: the bound is, per `@scope` rule set, the number of nodes the scoped rules are tested against times the number of scoping roots above each — at most N × depth entries of 12 bytes (a 5 000-node tree 20 deep with a root at every level: 100 000 entries, 1.2 MB, plus an `Rc` header and a map slot per node), freed when the pass ends (the memo lives in the pass's `Scratch`). Accepted at the Phase 2 gate: real `@scope` roots are few (components, not every level), so the lists are short; sharing a parent's list (generations stored relative to the parent) would make it O(N) but costs an extra walk per proximity read. Revisit if a profile shows the memo.

- **`ANIM-RELAYOUT-1` — a running geometry transition or animation lays the whole page out each frame.** C12-ANIMATABLE composites a running transition's value onto the element's computed style, so layout reads it; `layout_dom` is a whole-tree pass (there is no partial relayout), so every frame while a transition or CSS animation moves a longhand layout reads (`Longhand::affects_layout`: anything but the colors, `opacity` and the shadows) lays out every box. Since C12-KEYFRAMES a frame that moves only paint-only longhands — a `color` or `background-color` animation, an infinite pulse — composites and paints without a layout. A page with none running pays nothing (the frame is skipped; the cascade hook skips elements that declare no transition and no animation), and a running inheriting longhand restyles only the element's children. Pinned by `runtime::app::geometry_transition_tests::only_a_running_transition_costs_frames` (one layout per frame, no cascade) and `animation_event_tests::an_infinite_animation_costs_a_composite_per_frame_and_layout_only_for_geometry`. A `calc-size()`d box (an `auto` ↔ length transition under `interpolate-size: allow-keywords`) makes it two whole-tree layouts (`layout_pass::calc_size`). Paid down by a layout pass that re-lays out only the dirty subtrees and what their size changes reach.

## How to use this file

- **Adding an item.** ID format: `D-Mn-N` for milestone-specific deviations (where Mn is the milestone the work shipped in), `DRY-N` for refactor opportunities, `SUB-N` for substrate gaps, `OPS-N` for infrastructure, `M5-*` / `OPACITY-*` / `FOCUS-*` for topical groups.
- **Referring to an item.** Use the ID — `D-M2-2` etc. — in commit messages and PR descriptions.
- **Retiring an item.** Delete it. The historical context lives in the commit that retired it (`git log -S "D-M2-2"`).
